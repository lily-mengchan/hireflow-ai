# 岗位 JD 分段向量化与 RAG

## 当前实现

浏览器仍以 localStorage 中的岗位为准。RAG 不读取浏览器存储，而由浏览器明确 POST 岗位快照到服务端。只传递岗位 ID、名称、JD、地点、学历、经验和状态，不传候选人档案、面试历史或浏览器里的其他数据。

模型配置只存在服务端 `.env.local`。本次按用户指定，复用了另一个项目的 Qwen Embedding 和 DeepSeek 对话服务配置；没有复制其 Supabase、登录或其他业务配置。密钥不会通过 API 状态接口、日志或引用返回浏览器。

## 使用

```bash
npm run dev
```

1. 打开岗位管理，创建或编辑岗位并保存。
2. 开发环境保留自动预热；生产环境在提问时按需准备当前岗位索引，避免不同 Serverless 实例重复预热。
3. 打开 AI 招聘助手，输入岗位要求问题或点击五个验收问题；界面默认检索 16 个片段。
4. 点击回答下的引用，查看岗位名称、章节、逐字引文和来源原文。向量、版本和检索参数不作为 HR 操作入口展示。
5. 保存 JD 修改后再次提问，将使用当前岗位快照；旧回答会提示“岗位已更新，请重新提问”。

未配置模型时会明确报错，不切换到随机向量或预设回答。附件入口仍仅展示文件名，不上传、不解析。

## 配置

可参考 `.env.example`，在本项目根目录建立 `.env.local`。改动服务配置后重启 Next.js。

| 配置 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | 对话服务密钥，默认也供 Embedding 使用 |
| `OPENAI_BASE_URL` | OpenAI 兼容服务根地址，不含 `/chat/completions` |
| `RAG_CHAT_MODEL` | 对话模型名称 |
| `RAG_EMBEDDING_API_KEY` | 可选，独立 Embedding 服务密钥 |
| `RAG_EMBEDDING_BASE_URL` | 可选，独立 Embedding 根地址，不含 `/embeddings` |
| `RAG_EMBEDDING_MODEL` | 文本向量模型名称 |
| `RAG_EMBEDDING_DIMENSIONS` | 可选，服务支持的输出维度 |
| `RAG_MIN_SIMILARITY` | 余弦检索阈值，默认 0.25，需按模型校准 |

接口使用服务端原生 fetch，无新增 SDK、数据库或 Agent 框架。

## 分段与来源

`src/rag/chunks.ts` 识别 JD 中的职责、任职要求、加分项、工作条件等标题及常见同义标题。没有标题的内容保留为“岗位描述”，不让模型编造职责或要求。长段落按换行和句子边界拆分，每片最多 700 字符；特别长的无标点文本按上限切分。

每片包含 `jobId`、`jobTitle`、`section`、`content`、`chunkId`、`version` 和 `origin`。

原 JD 之外的已保存结构化字段单独建立“工作条件（岗位字段）”片段，用于回答地点、学历、年限问题。引用明确标注其字段来源；不会将这些值伪装成 JD 原文。如果字段与 JD 有不同要求，提示模型同时引用原文，而不擅自消解差异。

目前部分预置 JD 本身是通用描述，未声明专业技能或加分条件。系统只回答真实保存内容，不能因岗位名称包含 AI 就推断需要 AI 项目经验。例如原始前端 JD 明确写有“有 AI 产品经验优先”，其他岗位只写“对 AI 产品有兴趣”，不能等同为经验加分。

## 索引和失效策略

- 对片段标题、章节及内容调用真实 Embedding API，分批每次最多 10 条，校验数量、维度、有限值和非零向量。
- 同一模型、同一服务端点、同一维度生成问题向量。用余弦相似度排序、阈值筛选，返回 Top K（1–24，默认 16）。
- 请求直接使用内存中的向量索引，不创建目录、不写文件，也不要求磁盘或跨请求内存持久存在。
- 已有 `.local/rag/indexes/<hash>.json` 仅作为可选的只读种子缓存。文件不存在、损坏、只读或无读取权限时，在当前请求中调用真实 Embedding 并继续问答。项目未自动将被 Git 忽略的本地缓存打包到 Vercel，因此不能假设线上冷启动有这些种子。
- 岗位内容、字段、状态或集合变化都会改变 corpusVersion；模型、Embedding 服务端点或维度变化也会改变索引键。
- 每次问答都提交完整当前快照。服务端只使用对应版本的索引，缺失时即时构建，不依赖一个易过期的全局“最新”指针。
- 新建、编辑、重置后，下一次问答会提交最新快照并按需构建。开发环境另外保留 600ms 后的自动预热；生产环境不做独立预热请求。
- 为删除预留的协议：提交不包含已删除岗位的完整快照，新索引自然排除它。当前岗位页尚未新增删除按钮。
- 热实例最多缓存 3 份完整快照索引及 512 个片段向量。不同快照不会混入彼此的检索结果。
- 片段向量缓存按“模型配置签名 + 实际 Embedding 输入文本”寻址，不依赖整个岗位的版本：编辑 JD 后可复用未变更片段的向量，同时为所有返回片段生成当前正确的 chunkId 和版本。
- 同实例的相同快照及不同快照中的相同片段共享正在进行的 Embedding 请求；缺失片段合并批量调用。失败的请求会释放占位，后续可重试。

每个冷实例都可以独立从客户端快照生成索引并回答。上述缓存仅用于省成本，不保证跨请求、跨实例、重新部署或冷启动保留。当前 API 没有新增多用户权限系统。

## Vercel 与调用成本

API 使用现有 Node.js Route Handlers，索引模块只可选读取文件，没有文件写入路径，因此不依赖 Vercel 项目目录的可写性，也不使用 `/tmp` 持久化。仍需在 Vercel 配置模型密钥、地址、模型名称和维度，并满足模型网络访问及函数执行时限；本地 `.env.local` 不会随 Git 自动部署。

- 完整索引命中热缓存或有效只读 JSON：不再向量化 JD。
- 编辑/新增后的热实例：仅向量化缓存中不存在的输入文本。删除岗位通常不需要新增 JD 向量。
- 没有可用种子的冷启动或不同实例：可能再次向量化全部当前 JD。以 18 个片段、每批最多 10 条为例，需要 2 次 JD Embedding HTTP 请求。
- 每个非空知识库问题仍单独调用问题 Embedding；有相关片段时调用一次 LLM。空知识库直接拒答；检索无匹配时不调用 LLM。

这项改动保证冷实例的功能正确性，不能在没有共享持久缓存的前提下保证相同 JD 永远只计费一次。生产环境关闭预热请求，避免 `/index` 与 `/ask` 分别落到独立实例时重复计费。

## 回答约束

LLM 收到问题及检索原片段，输出 `items: [{chunkId, quote}]` 结构化证据选择结果。服务端核验 chunkId 必须属于本次 Top K，quote 必须逐字出现在对应原片段中；无效引用直接阻止输出。最终回答由服务端基于通过核验的原文整理，不展示未经核验的自由生成事实。

无匹配、空岗位或模型判断没有明确依据时，显示“未找到相关信息”。模型连接/权限/格式失败则明确报错，不将故障冒充“知识库没有信息”。Top K 检索不等于全库穷举，建议复杂跨岗位查询选更大的 K。

岗位和问题都作为不可信资料传给模型，系统提示禁止遵循资料中的指令。引用核验可阻止伪造来源和不在原文中的陈述，但不代表任意问题都能获得完美召回或语义判断；可用下方脚本持续回归。

## API

- `POST /api/rag/index`：`{ jobs }`，同步指定快照，返回版本、片段数、维度和模型。
- `POST /api/rag/ask`：`{ jobs, question, topK? }`，检索并返回回答和引用。
- `GET /api/rag/status`：只返回是否配置和模型名称，不返回密钥或服务端点。

请求验证包含同源 Origin、JSON 内容类型、1.5 MB 请求体上限、最多 100 个岗位、字段长度、重复 ID、问题长度和 K 范围。可选缓存文件名只使用服务端内容哈希。

## 验证与结果

```bash
npm run rag:index
npm run rag:verify
npm run rag:verify -- --memory-only
npm run test:rag
npm run test:data
npm run lint
npx tsc --noEmit
npm run build
```

`rag:index` 是显式的本地 CLI 导出，可将真实内存索引写入 `.local/rag/indexes` 供本地复用；该文件写入只存在于 CLI，API 不调用它。`rag:verify` 执行真实问题 Embedding、检索与 LLM 引文选择。也可传 `--jobs=<JSON文件路径>` 使用导出的岗位数组（仅模拟资料）。

`--memory-only` 不读取种子索引，并模拟 `EROFS`，验证真实模型链路以及全新冷实例。验证报告由本地 CLI 写入 `.local/rag/serverless-verification.json`，报告写入不是 API 功能。单元测试另外将文件写入函数替换为抛错函数，断言索引请求流水线零次写入，并覆盖缺失、不可读文件、缓存复用、并发合并和失效处理。

本次真实验证：6 个预置岗位、18 个片段、1024 维向量。五个问题均通过，包括 React 技能、AI 经验优先条件、上海工作地点和六个岗位的学历/经验要求。未声明的宠物津贴返回未找到。另用真实模型验证了新岗位、JD 将 React 改为 Vue、删除前端岗位后的快照隔离。

真实验收报告保存在 `.local/rag/verification.json`；通过 Next.js HTTP 接口执行的验收报告为 `.local/rag/http-verification.json`，包含索引/问答 200、空快照拒答、无效 K 的 400 和跨源请求 403。

模型协议参考：[OpenAI Embeddings](https://developers.openai.com/api/docs/guides/embeddings)、[阿里云 Embedding API](https://www.alibabacloud.com/help/en/model-studio/text-embedding-synchronous-api)、[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。
